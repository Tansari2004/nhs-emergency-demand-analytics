## Problems reproduced and corrected

The original validator compared row counts and some aggregate relationships but did not anchor every exported value to the database. Changing a historical delay count or replacing a backtest date with January 1900 still returned “Validation passed”. Further regression fixtures demonstrated acceptance of false backtest actuals/baselines with internally consistent MAEs, incorrect split metadata, a wrong preferred forecast, altered trust occupancy and a changed delay headline. A missing model prediction could be hidden by pandas' default skip-missing mean when the summary was changed accordingly.

The validator now:

- Opens SQLite read-only and compares all source columns for every monthly, quarterly and trust export.
- Rejects missing/nonfinite values, except the expected first-year missing year-on-year changes, which are checked against the derived series.
- Checks exact backtest dates, source actuals, same-month-last-year baseline, split metadata, preferred method/forecast, and every source-summary field.
- Reconciles MAE with a 0.051 absolute tolerance for forecasts rounded to one decimal place, without a relative tolerance that grows with the error.
- Supports `--snapshot powerbi/data` to compare all six checked-in CSVs with the full rebuild. CI runs that comparison, so a stale public snapshot fails verification.

The forecast entry point also rejects empty series and nonfinite, negative or fractional admissions. Numerical and workbook-reader versions used for the snapshot are pinned separately from the broader development dependency ranges.

## Forecast interpretation

The test is a **retrospective one-step evaluation using observed lags**. The random forest is fitted through August 2024 and stays fixed throughout the 24-month evaluation; the final model is refitted only afterward. The two source populations/time grains remain separate in SQL and reporting.

Chronologically earlier reporting months do not by themselves establish that data were published by a historical forecast issue date. The importer uses a later workbook, not historical release vintages. Release delays and revisions are not modelled. Accordingly, `as_of_month` identifies the last observation month, not a verified issue date or an information-availability cutoff. README and report notes now state this limitation explicitly.

Selecting the lower-MAE method on the same holdout makes the preferred result a comparison on this period, not an independently tested estimate of future superiority. A publication-aware, expanding-window evaluation and uncertainty intervals remain future work. No patient-level flow, causal relationship, clinical outcome, or operational deployment claim follows from this audit.
